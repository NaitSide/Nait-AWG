# Администрирование Nait-AWG

Основное описание и команда установки — в [README](../README.md). Здесь собраны подробности для настройки и обслуживания панели.

## Установка и порты

Поддерживается Ubuntu 24.04 x86_64. Совместная установка AmneziaWG 3.1 и панели предназначена для чистого VPS: найденные VPN, службы, интерфейсы и Docker-контейнеры, включая остановленные, останавливают установку. [Подробная инструкция и восстановление после ошибки](fresh-install.md).

Установка только панели проверяет совместимость существующего AWG 3.1. Она и обновление панели не перезапускают VPN-контейнер. Проверка из полного каталога исходников без установки:

```bash
sudo bash install.sh audit
```

TCP-порт панели по умолчанию — 443. Можно выбрать 443 или порт 1024–65535, кроме внутреннего 42842. Если выбранный порт занят, интерактивный установщик предложит свободный вариант; чужие службы не останавливаются. По умолчанию адрес — `https://IP/`, для другого порта — `https://IP:ПОРТ/`.

Если UFW уже включён, новая установка добавит разрешения для выбранного TCP-порта панели и TCP-порта 80 для сертификатов. Совместная установка также разрешает выбранный UDP-порт VPN. Установщик не включает UFW и не сбрасывает его политику. Правила сетевого экрана хостинга нужно настроить отдельно. При обновлении сохраняется порт панели и в активный UFW добавляется правило TCP/80 для сертификатов.

Установщик сначала предлагает RU или EN. Для запуска без выбора языка укажи `NAIT_AWG_LANG=ru` или `en`, например:

```bash
sudo env NAIT_AWG_LANG=en bash install.sh update
```

Без терминала и без переменной используется русский. Для неинтерактивной установки есть `NAIT_AWG_ACTION`, `NAIT_AWG_PUBLIC_ENDPOINT`, `NAIT_AWG_PANEL_PORT` и параметры совместной установки, описанные в [fresh-install.md](fresh-install.md). Занятый или неверный порт отменяет неинтерактивную установку.

## Клиенты, созданные до установки панели

Панель читает существующих peer и список клиентов AmneziaVPN. Действующие подключения сохраняются; доступны статистика, последнее рукопожатие, включение/отключение доступа и удаление клиента.

Закрытые ключи клиентских профилей, ранее выданных приложением AmneziaVPN, обычно не хранятся на сервере. Поэтому панель не может восстановить их исходный `.conf` или QR по одному серверному peer.

Значок рядом со статусом открывает пояснение и импорт исходного `.conf` или гостевого `.vpn` с одним AWG-подключением. Проверяется содержимое файла: ключ клиента, адрес, сервер, VPN-порт и общие параметры подключения. Профиль сохраняется в зашифрованной базе; действующее подключение не меняется. После импорта становятся доступны скачивание и QR. Полные бэкапы приложения, другие протоколы и профили с административными реквизитами не принимаются.

Удаление существующего клиента не требует его закрытого ключа. После подтверждения удаляются выбранный peer из работающего AWG и постоянного конфига, а также запись из списка AmneziaVPN. Перед изменением сохраняется резервная копия; при ошибке предусмотрен откат.

## Выдача конфигов и QR

Для сохранённого профиля доступны `.conf` AmneziaWG и гостевой `.vpn` AmneziaVPN с теми же клиентскими ключами. Имя подключения берётся из имени клиента в панели. Гостевой экспорт не содержит административного доступа к серверу.

QR AmneziaWG можно скачать или скопировать картинкой; для копирования картинки нужен HTTPS либо localhost. QR AmneziaVPN передаётся серией кадров, которые сменяются раз в секунду. Количество кадров зависит от размера конфига; иногда достаточно одного. Сканер приложения должен прочитать все части. Для составного QR кнопок скачивания и копирования нет.

В 0.1.1 правила новых экспортов сверены с исходным кодом AmneziaVPN 5.0.3.0. DNS, MTU и некоторые параметры зависят от выбранных настроек приложения и экспорта, поэтому одинаковые настройки нельзя вывести только из версии AWG. Обновление сохраняет старые профили и действующий `.env`; утраченные при старом импорте метаданные автоматически не восстанавливаются. [Правила, настройки и ограничения 0.1.1](config-export-0.1.1.md).

## Резервная копия и перенос

Экспорт создаёт снимок данных панели и VPN в JSON. Можно скачать его без шифрования или защитить паролем. Незашифрованный файл содержит секреты, позволяющие получить доступ к VPN.

| Входит в копию | Не входит в копию |
| --- | --- |
| Постоянный `awg0.conf`, включая серверный закрытый ключ и параметры обфускации | Логин и пароль администратора панели, её секрет сеансов |
| Список клиентов AmneziaVPN (`clientsTable`) | Реквизиты внутреннего Receiver |
| База клиентов панели и ключ для её расшифровки | Подключённый домен, сертификаты и состояние Let’s Encrypt |
| Имена, Telegram, заметки и история трафика | ОС, Docker-образ, пакеты, службы и сетевые правила сервера |
| Исходные настройки клиентских экспортов: endpoint, DNS, маршруты и keepalive | Полный `.env` или полный образ сервера |

Сам снимок содержит исходные настройки и ключи. Восстановление через панель выполняет **перенос клиентов**, с выпуском новых ключей и конфигов под целевой сервер.

1. Сохрани резервную копию заранее и скачай её с сервера.
2. Установи AmneziaWG и панель на целевом сервере. Проверь подключение и интернет на тестовом клиенте.
3. В настройках выбери «Восстановить», загрузи файл и введи пароль копии, если она зашифрована.
4. Проверь сводку и подтверди замену клиентов. Действующие клиенты целевого сервера будут заменены клиентами из копии.
5. Скачай и раздай новые конфиги. Ранее выданные файлы не переключаются на новый сервер автоматически.

Переносятся имена, Telegram, заметки, даты создания и история трафика; сохраняется включённое или отключённое состояние доступа. Адреса клиентов выделяются заново из подсети целевого сервера. История удалённых записей базы не восстанавливается как действующие клиенты.

Серверные ключи, VPN-порт, endpoint, DNS и маршруты клиентских экспортов используются с целевого сервера. Его параметры обфускации сохраняются по умолчанию; перенос старых параметров включается отдельным флажком. Параметры администратора панели и домен нужно настроить отдельно.

Текущая реализация выделяет адреса в IPv4-подсети `/24`; допускается перенос до 253 клиентов. Целевой AWG должен быть запущен, его постоянный и рабочий порты должны совпадать, а UDP-порт — быть опубликован Docker. Проверка файла и сервера не заменяет испытание VPN с реального устройства.

Перед заменой сохраняется состояние целевого сервера для отката. Если панель сообщает, что автоматический откат не завершён, требуется ручная проверка состояния.

## Обфускация

Редактор предназначен для работающего AWG 3.1. По умолчанию изменения закрыты; Edit mode сначала проверяет постоянный конфиг и работающий интерфейс.

«Случайные параметры» готовит черновик. Меняются HeaderProtectionKey, дополнения S1–S4 и клиентские junk-настройки; H1–H4 задаются различными значениями 1–4. Таймеры и сигнатурные пакеты сохраняются. Кнопка сама не применяет параметры: значения проверяются перед сохранением, затем требуется отдельное подтверждение с числом сохранённых и отсутствующих конфигов.

При изменении S1–S4, H1–H4 или HeaderProtectionKey потребуется заменить конфиги на устройствах. Панель обновляет сохранённые `.conf`, `.vpn` и QR с прежними клиентскими ключами и адресами. Уже разосланные файлы автоматически не меняются. Для клиентов без исходного профиля понадобится сохранённый конфиг и его ручное обновление либо выдача нового доступа.

Не меняй обфускацию, если единственный доступ к панели и SSH проходит через этот же VPN. Перед применением резервируется прежнее состояние, проверяется результат и предусмотрен откат. При потере ответа панель сверяет состояние через журнал; пока результат не подтверждён, выдача конфигов и новые изменения приостанавливаются. Обновление самой панели не меняет обфускацию. Новые параметры не гарантируют устранение сетевой блокировки.

## Домен и HTTPS

При установке создаётся самоподписанный HTTPS-сертификат для IP сервера. Подключение шифруется, но браузер предупреждает об отсутствии доверия к сертификату.

Для подключения домена:

1. Направь A-запись домена или субдомена на публичный IPv4 сервера. Если есть AAAA-запись, она также должна указывать на корректно настроенный адрес, иначе проверка может не пройти.
2. Освободи TCP-порт 80 на сервере и разреши его в сетевых экранах сервера и хостинга. Чужие веб-серверы панель не останавливает.
3. Введи домен без `https://`, порта и пути, укажи email и нажми «Сохранить». Подключение предполагает принятие условий Let’s Encrypt.

После успешного выпуска карточка показывает статус, срок сертификата и ссылку на панель. Автоматического перенаправления нет. На 443 адрес будет `https://ДОМЕН/`, для другого порта — `https://ДОМЕН:ПОРТ/`. VPN endpoint и клиентские конфиги не меняются. Сертификат домена не устраняет предупреждение при открытии панели по IP. Сохранение паролей зависит от браузера и его настроек.

Выпуск и продление выполняет `nait-awg-domain.service` через Certbot. Состояние хранится в `/var/lib/nait-awg-domain`, отдельно от обновляемых исходников. Проверка продления запускается при старте службы и каждые 12 часов; Certbot определяет, когда требуется продлить сертификат. DNS и доступность TCP/80 нужно сохранить. Порт 80 используется для проверки домена, HTTP-вход в панель на нём не добавляется.

Новый сертификат проверяется до применения и подхватывается без перезапуска панели или VPN. При ошибке предыдущий сертификат остаётся активным; если он уже истёк, доверенным от этого не становится. Диагностика:

```bash
sudo journalctl -u nait-awg-domain.service
```

## Администратор и вход

После установки терминал показывает адрес панели, логин `admin` и сгенерированный 12-символьный пароль. Сохрани реквизиты и смени пароль в настройках.

Чтобы изменить логин или пароль, включи Edit mode, введи текущий пароль и сохрани изменения. Для смены только логина оставь поля нового пароля пустыми. После сохранения прежние сеансы завершаются. Логин допускает 1–64 латинские буквы, цифры, точки, дефисы и подчёркивания.

Если забыл пароль, запусти установщик и выбери пункт 4. Из полного каталога исходников доступна та же операция:

```bash
sudo bash install.sh reset-auth
```

Сброс возвращает логин `admin`, создаёт новый пароль и завершает прежние сеансы. Перезапускается только панель; VPN, клиенты, порт и сертификат сохраняются. Предварительное обновление не требуется. При неудачном запуске панели установщик пытается вернуть прежние файлы авторизации.

Вход через форму и API имеет общие ограничения: до 10 попыток за 10 минут с одного адреса подключения и до 100 попыток за минуту суммарно. Учитываются удачные и неудачные попытки. При превышении возвращается HTTP 429 с временем ожидания. Счётчики находятся в памяти и сбрасываются при перезапуске панели.

Панель рассчитана на прямой HTTPS-доступ. Заголовки `X-Forwarded-*` не считаются доверенными; за обратным прокси все пользователи могут иметь общий лимит по адресу прокси. Изменяющие браузерные запросы проверяются по Origin и Sec-Fetch-Site; небраузерным запросам нужна авторизация. Панель запрещает встраивание в чужие страницы. Эти меры не заменяют сетевую защиту сервера.

## Версии и состояние AWG

Кнопка «Проверить» запрашивает последний опубликованный релиз `amneziawg-tools` и версию Nait-AWG из `package.json` ветки `main`. Для AWG в таблице сравнивается поколение протокола, а полный тег релиза доступен в подсказке и по ссылке. Это не проверка идентичности установленного Docker-образа или всех сборок движка. Сама кнопка ничего не обновляет.

Статус «Работает» требует запущенного контейнера, успешного чтения `awg show` и профиля AWG: адреса интерфейса, ключа сервера и клиентских параметров. Он не проверяет доступность UDP-порта из внешней сети или наличие интернета у клиента.

Для проверки доступности SSH из разных российских сетей можно использовать [iwtsy.com](https://iwtsy.com/). Это проверка TCP/SSH, а не подключение к AmneziaWG по UDP; одного результата недостаточно, чтобы установить причину сбоя VPN.

## Обновление и журналы

Обновление выполняется через пункт 3 установщика или из полного каталога текущих исходников:

```bash
sudo bash install.sh update
```

Сохраняются пользователи, реквизиты администратора, порт, сертификат и настройки. Контейнер VPN не перезапускается. Для локальной установки бери полный каталог исходников, включая `package-lock.json` панели и Receiver: зависимости ставятся через `npm ci`. Особенности сохранённых конфигов 0.1.1 и отката описаны в [отчёте об экспортах](config-export-0.1.1.md#сохранение-и-совместимость).

Установщик показывает этапы на выбранном языке. Подробный вывод установки пакетов, загрузки Docker-образа и библиотек сохраняется в отдельном root-only файле `/var/log/nait-awg-install.XXXXXX.log`; точный путь выводится при запуске. Пароли, генерация ключей, конфиги и интерактивные ответы в него не направляются. При ошибке установщик показывает последние сообщения и путь к сохранённому логу.

Если `sudo` до запуска установщика пишет `unable to resolve host`, проверь локальное разрешение имени сервера:

```bash
hostname
getent hosts "$(hostname)"
```

Если вторая команда ничего не выводит, проверь `/etc/hosts`: обычно нужна строка `127.0.1.1 ИМЯ_ИЗ_HOSTNAME`, с сохранением `127.0.0.1 localhost`.
